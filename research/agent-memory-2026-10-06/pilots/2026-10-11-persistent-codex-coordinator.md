## Reproduction and exact continuation

Use the [explicit coordinator instructions](../../../docs/codex-coordinator.md),
a dedicated fictional SQLite copy, one persistent native home, and a separate
same-filesystem journal. Keep source evidence and rubrics outside the receiving
namespace. The work fixture is described below; no real being enrollment is
needed. Use the qualified fork/model/configuration, not an unlabelled0.0.0 build.

1. Publish selected canonical heads and a short-lived annotated overlay. Verify
   the active view against the copied canon before initial receiving use.
2. Start a non-ephemeral native thread with the declared fictional binding. Save
   native UUIDs, effective configuration, original protocol results and available
   session files. Ask ordinary recall/action questions, not an HMK lookup command.
3. Run the local unit task, observe the failures/pass and actual native note.
   Terminate the process, then explicitly resume the same thread to establish
   process continuity. This pre-renewal diagnostic retains unincorporated notes;
   it is not permission to treat an expired view as fresh current context.
4. Stop writers. Source-qualify only the new procedure, supply changed-byte
   witnesses and stable event/stream sequence, and renew. On uncertain commit,
   resume the same operation without allocating a new ID. Preserve original
   native bytes before replacement. Recheck freshness before a new receiving task.
5. Correct a source through expected-revision APIs, then renew with current heads
   and an explicit empty new-learning selection when appropriate. Keep earlier
   heads. Verify expired text is absent across all active members.
6. Use a fresh thread for changed bindings. Reconstruct from a coherent checkpoint
   in a clean home, restoring selected necessary assets from the canonical
   artifact, with no original source sessions available. Compare actual reports,
   actions, relationships, results and uncertainty outside the receiver.
7. Disable native use/generation/startup in the receiving configuration; verify
   effective values and preservation of subsequent canon/native history. Never
   roll back by overwriting the new database with an old snapshot.
